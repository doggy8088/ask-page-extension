# 目前推理強度對應表

## 文件目的

本文件完整記錄 AskPage 支援的 AI Provider、預設模型、Thinking mode 能力、可否完全關閉、介面選項、預設值、API 欄位與目前實作限制，以利日後重新查核或調整。

**實際執行邏輯以 `content.js` 的能力常數與 `getReasoningCapability()` 為準。** 本文件對應版本為 `0.39.0`，查核與更新日期為 2026-08-02。

* * *

## 一、判定口徑

### 完全關閉

本文件只有在符合下列任一條件時，才將模型判定為可完全關閉 Thinking mode：

1. Provider 官方提供明確的 off 值，例如 `none`、`0` 或 `disabled`。
2. Provider 官方明確把該模式稱為 Non-Think 或 non-thinking。
3. 模型本身沒有可啟用的 reasoning／thinking mode；此類模型不需要顯示推理強度控制。

以下行為**不算完全關閉**：

- `minimal` 或 `low` 仍可能使用少量推理。
- 隱藏 reasoning／thinking 輸出，但模型仍在內部推理。
- API 只省略 thinking chunk，卻明確說模型仍會最低程度思考。
- 模型別名會被 Provider 動態切換，無法保證固定能力。

### 介面加入「關閉」的原則

**只有已由官方文件或即時模型 metadata 證實可完全關閉的 Provider 與模型，介面才會刻意加入「關閉」選項。**

介面內部值與顯示文字如下：

| 程式值 | 正體中文 | English | 意義 |
| --- | --- | --- | --- |
| `none` | 關閉 | Off | 明確關閉 Thinking mode |
| `minimal` | 最低 | Minimal | 最低推理，不代表關閉 |
| `low` | 低 | Low | 低推理強度 |
| `medium` | 中 | Medium | 中推理強度 |
| `high` | 高 | High | 高推理強度 |
| `xhigh` | 極高 | Extra high | 極高推理強度 |
| `max` | 最高 | Maximum | Provider 支援的最高推理強度 |

預算型控制另有以下值：

| 程式值 | 顯示 | 意義 |
| --- | --- | --- |
| `0` | 關閉 | 明確關閉 Thinking mode |
| `-1` | 動態 | 由模型動態決定推理 Token 預算 |
| 正整數 | `{數值} Token` | 指定推理 Token 預算 |

## 二、目前會顯示推理強度控制的 Provider

| Provider | 判定方式 | 是否包含「關閉」 |
| --- | --- | --- |
| Gemini | Gemini 完整模型 ID；Gemma 4 使用 `gemma-4-` 前綴 | 僅支援完全關閉的模型包含 |
| OpenAI | OpenAI 完整模型 ID | 僅官方支援 `none` 的模型包含 |
| Azure OpenAI | Deployment Name 必須等於已核准的完整模型 ID | 僅官方支援 `none` 的部署包含 |
| Anthropic Claude | Claude 完整模型 ID | 三個預設模型都包含 |
| DeepSeek | DeepSeek V4 完整模型 ID | 兩個 V4 預設模型都包含 |
| OpenRouter | 查核日 `/api/v1/models` metadata 的完整模型 ID | 僅 metadata 明確列出 `none` 的模型包含 |
| Ollama Cloud | `deepseek-v4-` 前綴 | DeepSeek V4 包含 |

下列 Provider 目前不顯示推理強度控制：

- Groq：目前可用的預設 reasoning model 無法完全關閉；曾支援 Off 的 Qwen3 已退役。
- Mistral AI：`reasoning_effort: "none"` 仍會最低程度思考，不符合本文件的完全關閉定義。
- 本機 Ollama：模型由使用者自行輸入，無法在 Provider 層級保證能力。
- OpenAI Compatible：endpoint 與模型皆由使用者自行輸入，無法安全推定參數相容性。

## 四、Gemini 與 Gemma 4

| `gemini-3.6-flash` | `minimal`、`low`、`medium`、`high` | `medium` | 否 | `generationConfig.thinkingConfig.thinkingLevel` |
| `gemini-3.5-flash-lite` | `minimal`、`low`、`medium`、`high` | `minimal` | 否 | `generationConfig.thinkingConfig.thinkingLevel` |
| `gemini-3.5-flash` | `minimal`、`low`、`medium`、`high` | `medium` | 否 | `generationConfig.thinkingConfig.thinkingLevel` |

| `gemini-3-flash-preview` | `minimal`、`low`、`medium`、`high` | `high` | 否 | `generationConfig.thinkingConfig.thinkingLevel` |
| `gemini-3-pro-preview` | `low`、`high` | `high` | 否 | `generationConfig.thinkingConfig.thinkingLevel` |

Gemma 4 的 Gemini API 使用 `minimal` 表示關閉。為了避免使用者把「最低」誤認為仍在推理，AskPage 介面改用 `none` 並顯示「關閉」，送出 request 時再映射回 `thinkingLevel: "minimal"`。舊版已儲存的 `minimal` 會自動正規化成 `none`，不會因升級而誤改為 `high`。

Gemini 3 系列的 `minimal` 對多數查詢可能接近無思考，但 Google 明確表示複雜任務仍可能進行最低程度推理，因此不加入 Off。

### 預算型模型

| 模型 | 預算範圍 | 可關閉 | 可動態 | 預設值 | API 欄位 |
| --- | --- | --- | --- | --- | --- |
| `gemini-2.5-pro` | `128` 至 `32768` | 否 | 是，使用 `-1` | `-1` | `thinkingBudget` |
| `gemini-2.5-flash` | `0` 至 `24576` | 是，使用 `0` | 是，使用 `-1` | `-1` | `thinkingBudget` |
| `gemini-2.5-flash-lite` | `512` 至 `24576`，另有 `0` | 是，使用 `0` | 是，使用 `-1` | `0` | `thinkingBudget` |

`gemini-flash-lite-latest` 是可由 Google 熱切換的別名，無法保證永遠對應相同模型或 Thinking 能力，因此不顯示控制。

代理模式可能加入 `includeThoughts: true` 以取得可用的推理摘要；這個欄位只控制是否回傳摘要，不會自行開啟已關閉的 Thinking mode。

官方依據：[Gemini Thinking](https://ai.google.dev/gemini-api/docs/generate-content/thinking)、[Gemma 4 on Gemini API](https://ai.google.dev/gemma/docs/core/gemma_on_gemini_api)、[Gemini 3.5 更新說明](https://ai.google.dev/gemini-api/docs/whats-new-gemini-3.5)。

## 七、Anthropic Claude

Anthropic 三個預設模型都會顯示推理強度控制，並刻意加入 Off。

### Claude Opus 4.7

| 項目 | 設定 |
| --- | --- |
| 模型 | `claude-opus-4-7` |
| 介面選項 | `none`、`low`、`medium`、`high`、`xhigh`、`max` |
| 預設值 | `none` |
| Off request | `thinking: { type: "disabled" }` |
| 開啟 request | `thinking: { type: "adaptive" }` |
| 強度欄位 | `output_config: { effort: ... }` |

### Claude Sonnet 4.6

| 項目 | 設定 |
| --- | --- |
| 模型 | `claude-sonnet-4-6` |
| 介面選項 | `none`、`low`、`medium`、`high`、`max` |
| 預設值 | `none` |
| Off request | `thinking: { type: "disabled" }` |
| 開啟 request | `thinking: { type: "adaptive" }` |
| 強度欄位 | `output_config: { effort: ... }` |

Opus 4.7 與 Sonnet 4.6 的 adaptive thinking 在未加入 `thinking` 時原本就是關閉。AskPage 仍會刻意送出 `thinking.type: "disabled"`，讓 Off 的 request 語意明確且可驗證。

啟用 adaptive thinking 時，`max_tokens` 由一般模式的 `4096` 提高為 `16384`，避免 Thinking 與回答共用過小的輸出上限。

### Claude Haiku 4.5

| 項目 | 設定 |
| --- | --- |
| 模型 | `claude-haiku-4-5` |
| 控制型態 | Thinking Token 預算 |
| 預算範圍 | `1024` 至 `32768` Token，另有 `0` |
| 預設值 | `0` |
| Off request | `thinking: { type: "disabled" }` |
| 開啟 request | `thinking: { type: "enabled", budget_tokens: N }` |

Haiku 4.5 不支援 adaptive thinking，必須使用 manual extended thinking。啟用後，AskPage 會把 `max_tokens` 設為 `budget_tokens + 4096`，最高不超過模型的 `65536` 輸出上限，保留至少 `4096` Token 給最終回答。

官方依據：[Anthropic Thinking](https://platform.claude.com/docs/en/about-claude/models/extended-thinking-models)、[Anthropic Extended Thinking](https://platform.claude.com/docs/en/build-with-claude/extended-thinking)、[Anthropic Effort](https://platform.claude.com/docs/en/build-with-claude/effort)。

官方依據：[Ollama OpenAI Compatibility](https://docs.ollama.com/api/openai-compatibility)、[Ollama Thinking](https://docs.ollama.com/capabilities/thinking)、[DeepSeek V4 on Ollama](https://ollama.com/library/deepseek-v4-flash:cloud)。

## 十三、本機 Ollama 與 OpenAI Compatible

### 本機 Ollama

本機 Ollama 沒有預設模型，模型由使用者輸入。Ollama 原生 API 對多數支援 Thinking 的模型提供 `think: false`，OpenAI 相容介面也接受 `reasoning_effort: "none"`，但模型可能有例外，例如 GPT-OSS 不能完全關閉。

AskPage 無法只根據使用者輸入的模型名稱安全判定能力，因此目前不顯示控制，也不會自動送出 `think: false`。

### OpenAI Compatible

OpenAI Compatible 的 endpoint 與模型都由使用者輸入。即使模型名稱與 OpenAI 或其他已知模型相同，也不能保證 endpoint 實作相同參數，因此不繼承任何 Provider 的能力表。

* * *

## 十四、設定保存與錯誤值處理

推理強度保存在 `chrome.storage.local` 的 `ASKPAGE_REASONING_EFFORTS`，以「Provider ID 加模型 ID」作為個別設定鍵：

- 同一 Provider 的不同模型分別保存。
- 相同模型在不同 Provider 不共用設定。
- 切換模型後會讀取該模型先前保存的值。
- 已保存值若不在目前能力表內，會回復模型預設值。
- 模型沒有能力設定時，`getReasoningCapability()` 回傳 `null`，介面不顯示控制，request 也不加入推理參數。
- Gemma 4 舊版的 `minimal` 保存值會遷移成介面 `none`，request 仍送出 `minimal`。

## 十六、程式碼與測試來源

主要實作位於 `content.js`：

| `OLLAMA_CLOUD_DEEPSEEK_V4_REASONING_CAPABILITY` | Ollama Cloud DeepSeek V4 能力 |
| `getReasoningCapability()` | 依 Provider 與模型取得能力 |
| `normalizeReasoningValue()` | 驗證保存值與處理舊值別名 |

| `applyDeepSeekReasoningConfig()` | 建立 DeepSeek thinking toggle 與 effort |

預設模型清單位於 `settings.js` 的 `PREDEFINED_MODELS`。

測試位於 `tests/reasoning-effort.test.js`，涵蓋：

- Provider 與模型隔離。
- 各模型允許的 effort 子集合。
- 所有明確 Off 選項。
- Gemma 4 `none` 到 API `minimal` 的映射與舊值相容。
- Anthropic adaptive／manual request 格式與輸出 Token 上限。
- DeepSeek `enabled`／`disabled` request 格式。
- OpenRouter 即時 metadata 對應。
- Ollama Cloud DeepSeek V4 Off。
- 未驗證模型不顯示控制。
