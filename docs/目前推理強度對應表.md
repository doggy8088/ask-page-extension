# 目前推理強度對應表

## 文件目的

本文件整理 AskPage 目前會在主對話框顯示推理強度滑桿的提供者、模型、可用值、預設值，以及送往各 API 的欄位格式。

**實際執行邏輯以 `content.js` 內的能力常數與 `getReasoningCapability()` 為準。** 本文件對應版本為 `0.39.0`，整理日期為 2026-08-02。

* * *

## 一、判定原則

推理強度控制採用提供者與模型的雙重判定：

1. 提供者類型必須符合能力表指定的類型。
2. 模型必須符合明確列出的完整模型 ID，或符合已核准的模型前綴。
3. 無法確認能力的提供者、模型別名或模型系列，不顯示推理強度控制。
4. 模型 ID 比對前會先轉為小寫、移除頭尾空白，並移除結尾的日期版本，例如 `o4-mini-2025-04-16` 會以 `o4-mini` 查表。

目前只有下列三類提供者會顯示推理強度控制：

| 提供者類型 | 判定方式 |
| --- | --- |
| Gemini | Gemini 完整模型 ID 對應表，另包含 `gemma-4-` 前綴規則 |
| OpenAI | OpenAI 完整模型 ID 對應表 |
| Ollama Cloud | `deepseek-v4-` 前綴規則 |

Azure OpenAI、Anthropic、DeepSeek、OpenRouter、Groq、Mistral、本機 Ollama 與一般 OpenAI Compatible 提供者目前都不顯示此控制項，即使模型名稱與表內模型相似也不會自動繼承。

## 二、介面值與顯示文字

等級型推理強度在程式內使用英文值，正體中文介面顯示以下文字：

| 程式值 | 正體中文顯示 |
| --- | --- |
| `none` | 關閉 |
| `minimal` | 最低 |
| `low` | 低 |
| `medium` | 中 |
| `high` | 高 |
| `xhigh` | 極高 |
| `max` | 最高 |

預算型推理強度另有以下特殊值：

| 程式值 | 正體中文顯示 | 意義 |
| --- | --- | --- |
| `-1` | 動態 | 由模型動態決定推理 Token 預算 |
| `0` | 關閉 | 關閉推理，但僅限明確支援關閉的模型 |
| 正整數 | `{數值} Token` | 指定推理 Token 預算 |

## 三、Gemini 與 Gemma 4 對應表

### 等級型模型

| 模型或前綴 | 可用值，依滑桿順序 | 預設值 | API 欄位 |
| --- | --- | --- | --- |
| `gemma-4-*` | `minimal`、`high` | `high` | `generationConfig.thinkingConfig.thinkingLevel` |
| `gemini-3.6-flash` | `minimal`、`low`、`medium`、`high` | `medium` | `generationConfig.thinkingConfig.thinkingLevel` |
| `gemini-3.5-flash-lite` | `minimal`、`low`、`medium`、`high` | `minimal` | `generationConfig.thinkingConfig.thinkingLevel` |
| `gemini-3.5-flash` | `minimal`、`low`、`medium`、`high` | `medium` | `generationConfig.thinkingConfig.thinkingLevel` |
| `gemini-3.1-pro-preview` | `low`、`medium`、`high` | `high` | `generationConfig.thinkingConfig.thinkingLevel` |
| `gemini-3.1-flash-lite` | `minimal`、`low`、`medium`、`high` | `minimal` | `generationConfig.thinkingConfig.thinkingLevel` |
| `gemini-3-flash-preview` | `minimal`、`low`、`medium`、`high` | `high` | `generationConfig.thinkingConfig.thinkingLevel` |
| `gemini-3-pro-preview` | `low`、`high` | `high` | `generationConfig.thinkingConfig.thinkingLevel` |

`gemma-4-*` 是前綴規則，目前設定頁內建的模型包括：

- `gemma-4-31b-it`
- `gemma-4-26b-a4b-it`

Gemma 4 在 Gemini API 上是開關式推理：`minimal` 表示關閉，`high` 表示開啟。

### 預算型模型

| 模型 | 一般預算範圍 | 可關閉 | 可動態調整 | 預設值 | API 欄位 |
| --- | --- | --- | --- | --- | --- |
| `gemini-2.5-pro` | `128` 至 `32768` | 否 | 是，使用 `-1` | `-1` | `generationConfig.thinkingConfig.thinkingBudget` |
| `gemini-2.5-flash` | `0` 至 `24576` | 是，使用 `0` | 是，使用 `-1` | `-1` | `generationConfig.thinkingConfig.thinkingBudget` |
| `gemini-2.5-flash-lite` | `512` 至 `24576` | 是，使用 `0` | 是，使用 `-1` | `0` | `generationConfig.thinkingConfig.thinkingBudget` |

代理模式會在 `thinkingConfig` 內額外加入 `includeThoughts: true`，讓回應中的推理摘要可納入執行過程顯示；詢問模式仍會送出使用者選定的 `thinkingLevel` 或 `thinkingBudget`，但不要求回傳推理摘要。

## 五、Ollama Cloud 對應表

| --- | --- | --- | --- |

- `deepseek-v4-pro`

其他 Ollama Cloud 模型不會因支援一般推理功能而自動顯示控制項；只有 `deepseek-v4-` 前綴會套用這份能力設定。

## 六、設定保存與錯誤值處理

推理強度設定保存在 `chrome.storage.local` 的 `ASKPAGE_REASONING_EFFORTS`，並以「提供者 ID 加模型 ID」作為個別設定鍵。因此：

- 同一提供者的不同模型可保存不同值。
- 相同模型在不同提供者設定中不會共用值。
- 切換模型後會讀取該模型先前保存的值。
- 如果保存值已不在目前能力表內，程式會回復該模型的預設值。
- 如果模型沒有能力設定，`getReasoningCapability()` 會回傳 `null`，介面不顯示滑桿，請求也不加入推理強度欄位。

## 七、程式碼來源

主要實作位於 `content.js`：

| 常數或函式 | 用途 |
| --- | --- |
| `GEMINI_REASONING_CAPABILITIES` | Gemini 完整模型 ID 能力表 |
| `GEMMA_4_REASONING_CAPABILITY` | Gemma 4 前綴能力設定 |
| `OPENAI_REASONING_CAPABILITIES` | OpenAI 完整模型 ID 能力表 |
| `OLLAMA_CLOUD_DEEPSEEK_V4_REASONING_CAPABILITY` | Ollama Cloud DeepSeek V4 前綴能力設定 |
| `getReasoningCapability()` | 依提供者與模型取得能力 |
| `normalizeReasoningValue()` | 驗證保存值並套用預設值 |
| `buildGeminiThinkingConfig()` | 建立 Gemini API 的 `thinkingConfig` |
| `applyOpenAIReasoningEffort()` | 建立 OpenAI 或 Ollama 相容的推理強度欄位 |

測試位於 `tests/reasoning-effort.test.js`，包含能力表、前綴判定、預算範圍、預設值、錯誤值回復與 API 請求格式。
